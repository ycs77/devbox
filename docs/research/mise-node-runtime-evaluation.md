# mise 管理 Devbox Node Runtime 的評估

> 研究日期：2026-10-22。只研究 mise、Node.js、Docker 的第一手官方文件及本 repo 現行 ADR；未執行安裝、Docker build 或實測。這是方案評估，不是架構決策。下文「官方文件」表示文件明載的能力或限制；「推論／建議」表示依據來源對 Devbox 契約的判斷，並非 mise 的保證。mise 文件會隨版本更新；採用前應以實際固定的 mise 版本文件與產出的 lockfile 為準。

## 決策摘要

**推論／建議：** mise 適合代管「從官方 Node archive 下載、依目標架構選檔、核對 checksum／可用時的 OpenPGP 簽章、安裝到獨立版本目錄」及 build 階段的 Node 版本解析；`mise.lock` 還可另外鎖各平台 archive 的 URL、checksum 與 backend。但它不會自動維持 Devbox 目前的 `/opt/devbox/runtimes/node/<release-line>` 目錄、Node global tool 安裝序列、容器啟動時的靜態 PATH、非 root 權限、單一共享 image 或不保存 Platform lock 的契約。若只想刪減 Node archive 驗證 recipe，仍須保留／重寫上述 Devbox 整合；若直接採用專案 `mise.toml`／`mise.lock`／shims，則是更廣泛的配置與 Runtime 選擇模型變更。[mise Node 安裝](https://mise.jdx.dev/lang/node.html#how-mise-installs-nodejs)、[mise lock](https://mise.jdx.dev/dev-tools/mise-lock.html)、[Docker](https://mise.jdx.dev/mise-cookbook/docker.html#install-project-tools-in-an-image)、[ADR-0048](../adr/0048-recipe-driven-runtime-build-without-platform-lock.md)、[ADR-0038](../adr/0038-container-local-runtime-path.md)、[ADR-0049](../adr/0049-static-project-sandboxes-from-global-build-inputs.md)

## 本 repo 的比較基準

- **repo 現況：** ADR-0048 不建立 Platform lock；Global config 指定要裝進下一份共享 Workspace image 的 Node release lines，打包的 Node recipe 固定 22→22.23.2、24→24.19.0。現行 `src/runtimes/node/build.ts` 在 Docker build 依當地架構驗證官方 archive 的簽署 manifest、解壓到 `/opt/devbox/runtimes/node/<release-line>`，接著執行 `npm install -g npm`、`npm uninstall -g corepack`、`npm install -g yarn pnpm @antfu/ni --allow-scripts=pnpm,yarn`。ADR-0048 所列的 Corepack pnpm 序列與現行程式碼不同；評估遷移時以執行中的 recipe 為準。這些額外工具未另鎖版本。[現行 Node build](../../src/runtimes/node/build.ts)、[現行 catalog](../../src/catalog/index.ts)、[ADR-0048](../adr/0048-recipe-driven-runtime-build-without-platform-lock.md)
- **repo 決策：** 一份共享 Workspace image 由 `devbox build` 建立；每個 Project 的靜態 Compose 按所選 Node 設 `NODE_VERSION`，`up` 不建 image；容器 PATH 應只放入 Project 所選 Runtime 的原生 `bin`，供 entrypoint、Compose exec、互動與非互動程序共用，而不是依賴 shell hook／shims。[ADR-0049](../adr/0049-static-project-sandboxes-from-global-build-inputs.md)、[ADR-0038](../adr/0038-container-local-runtime-path.md)
- **推論／限制：** 舊的 `docs/research/node-runtime-installation-source.md` 與已被取代的 Platform-lock ADR 不能當現行規格；mise 的專案 lockfile 是**可新增**的方案，不是 Devbox 已有的 Platform lock。[既有研究的 decision update](./node-runtime-installation-source.md)、[ADR-0048 status／decision](../adr/0048-recipe-driven-runtime-build-without-platform-lock.md)

## 1. Docker 安裝流程、安裝來源與供應鏈

- **官方文件：** `mise use node@24` 會安裝並寫入 `mise.toml`，其中 `"24"` 只是 release-line 前綴；`mise exec node@24 -- node --version` 缺工具時會下載，且不改設定或父 shell。`mise install` 安裝已配置工具，**不會自行選作預設或加入 PATH**；`mise exec -- …` 會把設定中的工具與環境加入單次 child process，缺工具時預設自動安裝。[Getting started](https://mise.jdx.dev/getting-started.html#run-a-tool)、[Getting started: share](https://mise.jdx.dev/getting-started.html#share-the-project)、[mise install](https://mise.jdx.dev/cli/install.html)、[mise exec](https://mise.jdx.dev/cli/exec.html)
- **官方文件：** 內建 Node backend (`core:node`) 預設由 `https://nodejs.org/dist/` 下載該平台官方預編譯 archive，對 `SHASUMS256.txt` 驗證 SHA-256；若該 release 提供簽章，預設也驗證 checksum 檔的 OpenPGP 簽章，不需另裝 `gpg`。安裝後檢查 `node -v`、`npm -v`；不設定 Node 專用環境變數，而是把該版本的 `bin` 放進 PATH。`node.mirror_url`／`MISE_NODE_MIRROR_URL` 可改變來源；檢查實際 backend 和產生的 lock URL，不能只由 `node` 名稱推斷始終從 nodejs.org 安裝。[Node: How mise installs Node.js](https://mise.jdx.dev/lang/node.html#how-mise-installs-nodejs)、[Node: mirror_url](https://mise.jdx.dev/lang/node.html#node.mirror_url)、[Node: verify](https://mise.jdx.dev/lang/node.html#node.verify)、[Node: gpg_verify](https://mise.jdx.dev/lang/node.html#node.gpg_verify)
- **官方文件：** `node.verify`、`node.gpg_verify` 預設為 true，但無發行簽章（`.sig` 為 404）時會略過簽章檢查；關閉 `node.verify` 會略過 checksum 檔及其簽章，lockfile 已有 checksum 則仍驗證該值。已安裝的同名 `node` plugin 會優先於內建 installer，故來源保證以實際 backend 與設定為條件；可信的 `mise.lock` 中 `backend = "core:node"` 可記錄 backend。[Node: verify／gpg_verify](https://mise.jdx.dev/lang/node.html#node.verify)、[Node: plugin precedence](https://mise.jdx.dev/lang/node.html#how-mise-installs-nodejs)、[lockfile reference: entry fields](https://mise.jdx.dev/dev-tools/mise-lock-reference.html#entry-fields)
- **官方文件：** 找不到該平台的 binary 時，Node backend 預設改為原始碼編譯；`node.compile = false` 禁止 fallback、無預編譯檔便失敗。Alpine／NixOS 的 `all_compile` 現行預設為 true，會優先編譯；改用預編譯檔時，musl 的 Node archive 來自 **unofficial builds** 而非 nodejs.org 官方 binary。來源編譯另需 Node build dependencies，產物不可直接視為官方 prebuilt archive。[Node: installation and compile](https://mise.jdx.dev/lang/node.html#how-mise-installs-nodejs)、[Node: unofficial builds](https://mise.jdx.dev/lang/node.html#unofficial-builds)、[Node: compile](https://mise.jdx.dev/lang/node.html#node.compile)
- **推論／建議：** 若 Devbox 要維持「官方 Node 二進位來源、沒有編譯 fallback」的邊界，Debian/glibc 目標可顯式使用 `core:node`、固定來源／驗證設定與 `node.compile = false`；不應把 Alpine/musl 的預編譯路徑描述成官方 Node binary。現有 release-key fingerprint 與 GPG keyserver fallback 的原始實作將改由 mise 的簽章驗證策略接手；這是信任實作移轉而非證明兩條驗證鏈逐位元等價。[Node installation](https://mise.jdx.dev/lang/node.html#how-mise-installs-nodejs)、[Node unofficial builds](https://mise.jdx.dev/lang/node.html#unofficial-builds)、[ADR-0048](../adr/0048-recipe-driven-runtime-build-without-platform-lock.md)

## 2. 版本鎖定：不同層次，不可混用

| 層次 | 官方文件明載 | 對 Devbox 的推論／取捨 |
| --- | --- | --- |
| Node release line／精確版本 | `node = "24"` 選最新的 24.x，`node = "24.11.0"` 指定該版；`mise use --pin` 可寫精確版本。[Node choosing a version](https://mise.jdx.dev/lang/node.html#choosing-a-version)、[Node pin npm](https://mise.jdx.dev/lang/node.html#pin-the-npm-version) | 僅填 24 無法代替 ADR-0048 目前打包 recipe 的精確版本；不帶 lockfile 的重建可能解析到較新 patch。[ADR-0048](../adr/0048-recipe-driven-runtime-build-without-platform-lock.md)、[Getting started: share](https://mise.jdx.dev/getting-started.html#share-the-project) |
| `mise.lock` | `mise lock` 不安裝工具，只寫解出的精確版本、backend、依平台 URL 及可取得時 checksum；`mise install --locked` 缺少相符條目或需要 URL 的 backend 缺目標平台 URL 時失敗。`mise lock --platform linux-x64,linux-arm64` 可備兩平台資訊；Node 範例有 `backend = "core:node"`、分平台 SHA-256／URL。[Lockfile quick start／strict mode／CI](https://mise.jdx.dev/dev-tools/mise-lock.html)、[lockfile reference](https://mise.jdx.dev/dev-tools/mise-lock-reference.html#file-format) | 應明確提交 `mise.toml`、`mise.lock` 並讓 Docker COPY 二者後 `mise install --locked`；若額外鎖 `npm:` 等工具的相依圖，還須帶 `.mise/locks/`。這會新增 Devbox 現行沒有的持久鎖檔更新與審查工作。[mise Docker install](https://mise.jdx.dev/mise-cookbook/docker.html#install-project-tools-in-an-image)、[ADR-0048](../adr/0048-recipe-driven-runtime-build-without-platform-lock.md) |
| 所下載的 bytes | 有 checksum 時下載檔受 checksum 限制；lockfile 的 URL／checksum 依 backend 可取得資料而異；鎖定不等於離線，也不保證 source build output。已安裝的樹或還原的 install cache **不會**對 lock 重算驗證。[Lockfile backend support／restored caches／provenance](https://mise.jdx.dev/dev-tools/mise-lock.html) | 查實際 Node platform entry，不能宣稱每個 release／來源都有相同來源驗證；需防範 writable install cache 篡改；「build 完成後 runtime tree 永遠 immutable」應由 image 與權限政策實現，不是 `--locked` 自動提供。[同上](https://mise.jdx.dev/dev-tools/mise-lock.html#restored-caches-and-installed-tools) |
| mise 本體／基底 image | 官方 `ghcr.io/jdx/mise` 有 full-version 與會移動的 month／`latest`／`debian` tags；同版本 tag 在重建後仍可指向不同 image，使用 OCI digest 才精確固定。`mise.lock` 僅鎖工具，不鎖應用依賴。[mise Docker official images／digest](https://mise.jdx.dev/mise-cookbook/docker.html#official-images)、[mise lock quick start](https://mise.jdx.dev/dev-tools/mise-lock.html#quick-start) | mise image tag、Docker Base digest、Node 工具 lock、npm/pnpm/yarn 版本及 Project lockfile 是不同鎖定範圍；任何一個都不能替代其餘。[同上](https://mise.jdx.dev/mise-cookbook/docker.html#pin-an-image-by-digest)、[Node package managers](https://mise.jdx.dev/lang/node.html#package-managers) |

- **官方文件：** `mise.lock` 不是應用程式 dependency lock；仍須保留 `package-lock.json` 等。Core archive 依平台記錄 URL 和可取得 checksum；`--locked` 查不到平台條目時不能偷偷重新解析。已鎖版本可避開查詢版本清單，但首次 archive 下載／驗證仍需要網路。正式使用前要審查 lockfile 的 URL、checksum、backend 和來源設定；lock 的 checksum 是受信任輸入。[Lockfile quick start／strict mode／CI／backend support](https://mise.jdx.dev/dev-tools/mise-lock.html)、[Lockfile provenance](https://mise.jdx.dev/dev-tools/mise-lock.html#provenance-and-verification)
- **官方文件：** `mise exec node@latest -- …` 之類明確命令列版本可繞過 lockfile；`mise exec` 預設可自動安裝缺少工具，shims 缺工具時也可自動安裝或 fallback 至系統同名指令。**推論／建議：** 嚴格固定的 Runtime 不可把任意 `mise exec node@latest` 或可自動安裝的 shim 當成唯一版本／完整性邊界。[lockfile reference: command reads](https://mise.jdx.dev/dev-tools/mise-lock-reference.html#which-lock-entry-a-command-reads)、[mise exec](https://mise.jdx.dev/cli/exec.html)、[shims fallback](https://mise.jdx.dev/dev-tools/shims.html#how-shims-work)

## 3. npm、Corepack、pnpm、Yarn：Node 鎖不涵蓋它們全部

- **官方文件：** Node archive 隨附 npm；可在 `[tools]` 另外指定 `npm = "11"`，其 executable 在 mise 環境會優先於 Node 內建 npm。`mise use --pin node@lts npm@latest` 會把解析出的版本寫入配置。mise 也可另外安裝 npm、pnpm、Yarn，且不仰賴 Corepack；若專案沒有宣告 package-manager 版本，mise 不會像 Corepack 那樣自選 known-good 版本。[Node package managers／pin npm](https://mise.jdx.dev/lang/node.html#package-managers)、[Node packageManager](https://mise.jdx.dev/lang/node.html#package-manager-versions-in-package-json)
- **官方文件：** `node.corepack` 預設 false；設 true 時僅在含 Corepack 的 Node 安裝後執行 `corepack enable`。Node 官方說 v25 起**不再隨 Node 散發 Corepack**，故 v25+ 若需要 Corepack 須另選安裝來源／版本。`node.npm_shim` 在 macOS/Linux 預設會以包裝器取代該版本 `bin/npm`，global npm install/uninstall 後執行 `mise reshim`；若需要保留上游 npm executable 或讓 Corepack 控管 npm 可關閉。[Node corepack／npm_shim](https://mise.jdx.dev/lang/node.html#node.corepack)、[Node.js v24 Corepack](https://nodejs.org/docs/latest-v24.x/api/corepack.html#corepack)、[mise npm_shim](https://mise.jdx.dev/lang/node.html#node.npm_shim)
- **官方文件：** 一般 `npm install -g` 安裝到目前 Node 版本（除非 `.npmrc` 覆寫 prefix），切換 Node 後不會自動擁有同一 CLI；另外裝成 `npm:` 工具才可跨 Node 版本使用。`mise.lock` 對獨立 `npm:` 工具的新版格式可鎖其 transitive graph 至 `.mise/locks/`，但 lifecycle scripts 仍可能在不同環境得到不同結果；**這不是**對 Node archive 內建 npm 或專案 `node_modules` 的鎖定。[Node global npm packages](https://mise.jdx.dev/lang/node.html#global-npm-packages)、[lockfile dependency graphs](https://mise.jdx.dev/dev-tools/mise-lock.html#dependency-graphs)
- **推論／建議：** 現行 build 的 `npm install -g npm`、移除 Corepack、全域安裝 Yarn／pnpm／`@antfu/ni` 有特定命令歸屬與浮動版本；單純改成 `mise use node@24` 不會保留該序列與 pnpm/Yarn 行為。要逐一決定保留現行 npm 全域安裝（自行管版本／可變 prefix）、改成 mise 分別宣告工具（PATH 優先順序與全域工具的歸屬會改變），或部分使用 Corepack；不應把 Node 的 `mise.lock` 誤稱為既有全套 Node 工具鎖。[現行 Node build](../../src/runtimes/node/build.ts)、[mise Node package managers](https://mise.jdx.dev/lang/node.html#package-managers)

## 4. 容器啟動、PATH 與權限

- **官方文件：** Docker cookbook 的 Debian 例子 `COPY mise.toml mise.lock ./` → `RUN mise trust && mise install --locked` → `CMD ["mise", "exec", "--", "node", "server.js"]`；build 的非互動式 shell 不跑 activation hook，`RUN`／`CMD` 應用 `mise exec -- …` 或 `mise run …`。COPY binary 的例子另須自行裝 CA certificates、設 mise data/config/cache 目錄與 PATH；scratch image 不能當有 shell／package manager 的 build base。[mise Docker: install／copy binary](https://mise.jdx.dev/mise-cookbook/docker.html#install-project-tools-in-an-image)、[Docker official images](https://mise.jdx.dev/mise-cookbook/docker.html#official-images)
- **官方文件：** `mise activate` 為互動 shell 在 prompt／cd 更新 PATH；`mise exec` 只修改 child process 與後代，`mise run` 則為 task；shims 每次呼叫按工作目錄選版本，與 activation 的直接版本 `bin` 不同，`which` 會先顯示 shim，`command -v node` 可能只有 shim 而尚未安裝 Node。shims 另有每次啟動解析的開銷與預設同名系統 command fallback。Node installer 預設位置是 `~/.local/share/mise/installs/node/<version>`，可移動 `MISE_DATA_DIR`／`MISE_INSTALLS_DIR`，但官方建議用 `mise where/which` 而不是硬拼路徑。[Getting started activation](https://mise.jdx.dev/getting-started.html#activate-mise)、[shims comparison／performance](https://mise.jdx.dev/dev-tools/shims.html)、[directories](https://mise.jdx.dev/directories.html#installs)
- **推論／建議：** 可在 build-time 以 mise 安裝，然後在 Devbox Compose／entrypoint 對所選版本提供**固定的實際安裝 `bin` PATH**；但要新增從 release line → 已安裝精確版本 → 路徑的可靠映射，並確認 npm/Corepack global commands 可見、非選用 Node 不進一般 PATH。若採 `mise exec` 做 runtime selector，須把 entrypoint、Agent、Compose-exec、非互動 shell 都納入 wrapper，並處理首次自動下載對靜態 image 與非 root 權限的影響；官方 cookbook 的 CMD 例子不能直接替代 ADR-0038 的容器環境 PATH。[ADR-0038](../adr/0038-container-local-runtime-path.md)、[mise exec](https://mise.jdx.dev/cli/exec.html)、[mise install](https://mise.jdx.dev/cli/install.html)
- **官方文件：** 官方 mise scratch／Debian images 僅帶 mise、未預裝 Node；皆把 `MISE_DATA_DIR=/mise`、`MISE_CONFIG_DIR=/mise`、`MISE_CACHE_DIR=/mise/cache`、`/mise/shims` 加入 PATH。Debian variant 為 Debian 13 slim，附 `ca-certificates`、`curl`、`git`、`libatomic1`，而從 scratch `COPY --from` **僅複製 binary**，不帶原 image 的憑證及 ENV。[mise Docker official images／copy binary](https://mise.jdx.dev/mise-cookbook/docker.html#official-images)
- **官方文件：** 多使用者或 root build 可 `mise install --system` 於 `/usr/local/share/mise/installs`，各 user 的 mise 可讀取相符版本；仍須各 user config／`mise exec` 選用，並不直接將 executable 放 PATH。root 在 Docker build 執行受支援；一般使用者若目的地不可寫，部分 backend 可經 sudo 發布，但 **core tools（Node）需可寫目的地或以 root 直接安裝**，非互動 sudo 否則可能失敗。使用者自己的安裝會優先於 system 安裝；官方 image 的共用 `/mise` config/data/cache 不適合未隔離的多 user，需調整。[mise system installs](https://mise.jdx.dev/dev-tools/system-installs.html)、[mise Docker share between users](https://mise.jdx.dev/mise-cookbook/docker.html#share-tools-between-users)
- **推論／建議：** 若 Devbox 由 root 建 image、Sandbox 是非 root，優先讓 build-time 安裝樹與所需 executable 可讀／可執行，將 Runtime 變更限制在 image build；如使用 `/mise` 的 user installs，需明確檢查 root-owned 目錄的 read/execute、後續 cache/state/shim 寫入與 Agent home mount 的相互作用；如用 `--system`，PATH／配置選用仍由 Devbox 負責。mise 官方並沒有保證把其 install tree 直接 relocation 到 `/opt/devbox/runtimes/node/<line>` 後一切照常運作；不要在未決定目錄、映射、ownership 前假定它是 drop-in replacement。[Docker multi-user／official image dirs](https://mise.jdx.dev/mise-cookbook/docker.html#share-tools-between-users)、[system installs](https://mise.jdx.dev/dev-tools/system-installs.html)、[directories](https://mise.jdx.dev/directories.html)、[ADR-0038](../adr/0038-container-local-runtime-path.md)
- **官方文件：** `mise.toml` 的 `[env]`、hooks、設定可執行程式或改環境；mise Docker 範例先 `mise trust`，CI 模式預設信任設定。官方建議用 `.dockerignore` 排除 `.env`、`*.local.toml` 等個人覆寫／憑證。**推論／建議：** 只讓 machine-owned config 進 image；若改讀 Project workspace 的 mise 配置，信任界線、build context 與秘密排除範圍會變大，不能因有 lockfile 就忽略 config 執行風險。[mise security: trust／CI](https://mise.jdx.dev/security.html#configuration-trust)、[mise Docker build context](https://mise.jdx.dev/mise-cookbook/docker.html#what-to-copy-into-the-build)

## 5. 平台與多架構

- **官方文件：** 2026.9.11 起官方 mise images 對 `linux/amd64` 與 `linux/arm64` 都發布 scratch／Debian variants；full version tag 固定 release，digest 固定 image 內容。`mise lock --platform linux-x64,linux-arm64` 可在同一 lockfile 存兩種 Node archive URL／checksum；musl 另有 `linux-x64-musl`／`linux-arm64-musl` keys。Docker multi-platform manifest 會依目標架構挑相應 image，跨架構 RUN 需要 native builder 或 QEMU 等可執行環境；**multi-arch mise image 本身不表示產出的 Workspace image 自動包含兩種 Node binary**。[mise Docker official images／digest](https://mise.jdx.dev/mise-cookbook/docker.html#official-images)、[mise lock platform keys](https://mise.jdx.dev/dev-tools/mise-lock-reference.html#platform-keys)、[Docker multi-platform](https://docs.docker.com/build/building/multi-platform/)
- **官方文件：** minimal scratch／busybox／distroless 中缺 linker 線索時 libc 偵測可能失準，可設定 `MISE_LIBC=musl`／`glibc`；mise 的 static-musl executable 可在 glibc 與 musl base 運作，但**不代表下載的 Node 也跨 libc**。Node 官方在不同 major release 的 OS、glibc、libstdc++ 要求各異；Node 25 起官方 Linux binary 另需 libatomic runtime，mise Debian image 附 `libatomic1`，自建 image 需自行處理。[mise Docker libc](https://mise.jdx.dev/mise-cookbook/docker.html#override-libc-detection)、[Node build platform requirements](https://github.com/nodejs/node/blob/main/BUILDING.md#official-binary-platforms-and-toolchains)、[mise Docker official images](https://mise.jdx.dev/mise-cookbook/docker.html#official-images)
- **推論／建議：** 若 Devbox 保留現行「依本機 Docker 架構 build 一份共享 image」即可分架構安裝；若未來發佈 multi-platform image，需逐平台建／驗證該平台的 Node binary 與 OS library，並一併 lock 所需平台 URL/checksum。若選擇 source fallback 或 musl unofficial build，必須另立來源與平台政策，不可把另一平台的 lock checksum 當共用 checksum。[ADR-0048](../adr/0048-recipe-driven-runtime-build-without-platform-lock.md)、[mise Node installation／unofficial builds](https://mise.jdx.dev/lang/node.html#how-mise-installs-nodejs)、[lockfile reference](https://mise.jdx.dev/dev-tools/mise-lock-reference.html#platform-keys)

## 可供決策的選項

1. **只替換 Node 下載／驗證實作：** [推論] build-time 用固定版 mise + `core:node` + 精確版本 + 禁止編譯 fallback；Devbox 仍自行維持 Runtime 路徑契約、npm/Corepack/Yarn 序列、非 root PATH 及 image 組裝。優點是省下 archive 解析／簽章驗證的自管邏輯；代價是多了一層 mise installer、版本及目錄映射與供應鏈審查。[mise Node installer](https://mise.jdx.dev/lang/node.html#how-mise-installs-nodejs)、[ADR-0048](../adr/0048-recipe-driven-runtime-build-without-platform-lock.md)
2. **完整改採 mise 配置／鎖／selector：** [推論] 提交 machine-owned `mise.toml`／`mise.lock`，針對 build 平台鎖 archive 並在 Docker 跑 `mise install --locked`；另決定是否使用 `mise exec` 或直接 PATH、是否獨立宣告 package managers。優點是把解析、跨平台 archive checksums、工具 backend 與更新交給 mise；代價是取代 ADR-0048 的無 Platform-lock recipe 模型、重新定義 ADR-0038 的 PATH／路徑，仍無法把應用依賴或已安裝的 Runtime 樹視為由 lock 全面驗證。[mise lock](https://mise.jdx.dev/dev-tools/mise-lock.html)、[mise Docker](https://mise.jdx.dev/mise-cookbook/docker.html#install-project-tools-in-an-image)、[ADR-0048](../adr/0048-recipe-driven-runtime-build-without-platform-lock.md)、[ADR-0038](../adr/0038-container-local-runtime-path.md)
3. **維持既有 recipe：** [推論] 如果首要約束是「精確的 `/opt/devbox/runtimes/node/<line>` 原生 PATH、既有 global-tool ownership、沒有另存 mise lock」，目前已由 ADR-0048 定義這條路，加入 mise 反而可能增加比刪除更多整合碼。對來源驗證仍應維持現行 build-time 簽署 manifest／archive 核對，不可只保留版本字串。[ADR-0048](../adr/0048-recipe-driven-runtime-build-without-platform-lock.md)、[mise install layout](https://mise.jdx.dev/directories.html#installs)
