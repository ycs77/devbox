# Resolve floating-latest AI Agents during every Workspace build

ADR-0041 supersedes this decision completely: Configured Agents are no longer Workspace build inputs and are installed only when an eligible Sandbox lacks a completed first-start bootstrap.

The Configured Agent set selects Agent names only. Every `build` installs each configured Agent's then-current floating `latest` through its packaged family-specific recipe and official upstream installation source, while forcing the Agent installation stages to bypass BuildKit cache. Agent versions remain outside the Platform lock, Devbox package data, and any separate Agent lock or registry; `update` neither resolves nor changes them, and Sandbox startup never installs or updates an Agent executable.

Agent stages resolve independently during Docker execution, so one Workspace build may contain Agent releases observed at slightly different times and repeats their downloads even when upstream versions have not changed. Devbox accepts that cost and weaker reproducibility for fast updates without persistent version state. Any Agent-stage or later Docker failure leaves the prior `devbox-workspace:latest` usable under ADR-0032's forward-only publication rule; a successful Docker build is still the complete build contract, with no post-build Agent verification or persisted version record.

Each Agent recipe installs its executable under an isolated image path and exposes a read-only command projection. Generated Compose adds projections only for the current Configured Agent set and mounts homes only for that set, regardless of extra Agent contents in a stale image. Before the long-lived Sandbox process starts, entrypoint preflight requires every configured projection to exist; a missing Agent reports its name, directs the user to run `devbox build` and then `devbox up`, and exits nonzero. Extra Agents left in a stale image remain outside the supported `PATH`, while a missing configured Agent prevents readiness. This structural check does not add post-build version or executable verification.
