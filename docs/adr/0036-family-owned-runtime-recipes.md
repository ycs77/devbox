# Let each Runtime family own its installation recipe

Devbox gives each Runtime family its own packaged recipe behind one Build-module seam: the recipe consumes that family's exact Platform-lock entry and emits a Base-profile-compatible Runtime tree at `/opt/devbox/runtimes/<family>/<release-line>` inside the generated Workspace Dockerfile. Recipes may use different installation mechanisms—archive extraction, distribution packages, compilation, or an external image stage—without exposing those differences through a generic installer DSL or preparing Runtime contents on the host; ADR-0033 and ADR-0035's machine-owned context and single inline Docker build remain in force.

Node recipes install the official precompiled Linux binary tarball directly rather than relocating `/usr/local` from the Docker Official Node image. `update`, or bootstrap `build`, resolves the exact Node revision and target-platform archive, and Build verifies its official signed checksum before extracting it into the release-line path; the Platform lock identifies the exact archive and SHA-256 rather than a Node source image and OCI digest. This accepts Devbox ownership of Node archive verification and architecture mapping in exchange for a source-independent recipe model, direct isolated installation, and avoiding image-specific Yarn, entrypoint, account, symlink, and shared-library relocation behavior.

The Platform lock records one top-level target platform inherited by its Base and every Runtime entry. Each Node entry records the exact revision, archive URL and SHA-256, signed-checksum manifest URL, and full OpenPGP fingerprint of the signer that authenticated that manifest for that target. The Devbox package owns the trusted Node release-key keyring; resolution accepts only a packaged trusted signer, while every Build re-downloads the locked manifest and archive, verifies the manifest with that keyring and requires the locked signer, then verifies the selected archive against the locked SHA-256 before extraction.

This supersedes ADR-0005's Node source-image relocation while preserving isolated Runtime contents and Runtime-recipe ownership of package managers. It also supersedes ADR-0007's Node source-image, OCI-digest, and locked package-manager fields; ADR-0041 owns the floating Sandbox-bootstrap package-manager lifecycle.
