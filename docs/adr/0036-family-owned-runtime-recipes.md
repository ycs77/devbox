# Let each Runtime family own its installation recipe

> **Current status (2026-08-14):** ADR-0048 keeps family-owned Runtime recipes but supersedes this ADR's Platform-lock consumption and fingerprint-snapshot contract. The Node recipe fixes `22.23.2` and `24.19.0` for release lines 22 and 24 and owns the complete verified prototype flow.

Devbox gives each Runtime family its own packaged recipe behind one Build-module seam: the recipe consumes that family's Platform-lock entry and emits a Base-profile-compatible Runtime tree at `/opt/devbox/runtimes/<family>/<release-line>` inside the generated Workspace Dockerfile. Recipes may use different installation mechanisms—archive extraction, distribution packages, compilation, or an external image stage—and may keep release-line-specific source and trust policy without exposing those differences through a generic installer DSL or preparing Runtime contents on the host; ADR-0033 and ADR-0035's machine-owned context and single inline Docker build remain in force.

Node recipes install the official precompiled Linux binary tarball directly rather than relocating `/usr/local` from the Docker Official Node image. `update` resolves the exact Node revision, target-platform archive URL, and signed-checksum manifest URL without downloading the archive or authenticating its signature; Build performs those downloads and verifies the manifest and selected archive before extracting the Runtime into `/opt/devbox/runtimes/node/<release-line>`. Each packaged Node release-line recipe owns its hard-coded trusted release-key fingerprint list, while `update` snapshots that list into the corresponding Platform-lock entry. This accepts Build-time source verification and possible future archive replacement in exchange for a small source-coordinate plan and a recipe model independent of the Node image.

The Platform lock records one top-level target platform inherited by its Base and every Runtime entry. Each Node entry records the exact revision, archive URL, signed-checksum manifest URL, and trusted release-key fingerprints; it does not record the Node archive SHA-256 or the signer observed during Build. Build retrieves public keys using the recipe's keyserver policy, accepts a manifest signed by any fingerprint in the locked list, derives the archive checksum from that verified manifest, and verifies the archive before extraction. The Base digest remains locked separately.

This supersedes ADR-0005's Node source-image relocation while preserving isolated Runtime contents and Runtime-recipe ownership of package managers. It also supersedes ADR-0007's Node source-image, OCI-digest, and locked package-manager fields; ADR-0041 owns the floating Sandbox-bootstrap package-manager lifecycle. ADR-0047 records the later decision to move Runtime source verification into Build and snapshot release-key fingerprints rather than archive digests in the Platform lock.
