# Keep one machine-owned Workspace build context

Devbox keeps the single generated common Workspace build context directly at `~/.devbox/build/`, with its Dockerfile, defensive `.dockerignore`, and only the packaged recipe assets required by the current build set. The explicit `build` command regenerates the complete machine-owned contents from Global `node`, `agent`, and `agent_notifications` configuration plus packaged recipes, renders Node Runtime and Agent entries in the order they appear in Global configuration, and invokes one `docker build` operation with that directory as its context. Devbox does not reorder those entries canonically, so reordering the same Global entries changes the generated Dockerfile layer order and may invalidate Docker's layer cache. The current prototype keeps the Base and Runtime stages inline in that one Dockerfile rather than publishing any separate Base image.

Devbox never uses `~/.devbox` itself as a Docker build context because it contains the Project registry, Global configuration, future Project state, and retained Compose state that must not be sent to Docker. Build must serialize access to its shared context, but no Platform-lock coordination or lock-file read is part of the current recipe-driven decision. A later invocation overwrites incomplete or stale generated contents rather than trusting them as prepared state.

Every `build` overwrites the packaged `.bash_aliases`, `.gitconfig`, and enabled Agent defaults (`AGENTS.md`, `.claude/settings.json`, and `.omp/agent/config.yml`) with the current Devbox package contents before invoking Docker. Package upgrades and manual edits in this generated directory therefore cannot leave stale defaults in the next Workspace image. Build removes known packaged Agent asset files that the current Configured Agent set no longer needs; it does not recursively delete unrelated files or directories. The defensive `.dockerignore` excludes unrelated files from the Docker context.

This refresh is confined to `~/.devbox/build/`. Agent homes in external Docker volumes, their credentials and mutable settings, and Claude's user-owned `~/.devbox/agents/claude/.claude.json` are persistent user data, not build inputs. Build neither overwrites nor deletes them. Updated image defaults initialize new Agent homes; rebuilding does not replace defaults already stored in an existing Agent home.
