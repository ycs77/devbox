# Keep one machine-owned Workspace build context

Devbox keeps the generated common Workspace build context at `~/.devbox/build/workspace/`, with its Dockerfile, defensive `.dockerignore`, and only the packaged recipe assets required by the current build plan. The explicit `build` command regenerates the complete machine-owned contents from the fully resolved Base and Configured Runtime set, orders variable entries canonically, and invokes one `docker buildx` operation with that directory as its context. ADR-0041 removes the Configured Agent set from this context because every Sandbox installs Agents during first-start bootstrap independently of its Toolchain. The fixed path is not a success marker, cache identity, user-editable interface, or persisted candidate: each Build invocation may replace it before Docker work, failure leaves no dirty state, and Cleanup may remove it only while holding the same exclusive user-scope lifecycle lock that serializes Build.

Devbox never uses `~/.devbox` itself as a Docker build context because it contains the Project registry, Global configuration, Platform lock, and per-Project Local and retained Compose state that must not be sent to BuildKit. Build serializes access to the shared context while holding the exclusive user-scope lifecycle lock for its complete operation, and a later invocation overwrites incomplete or stale generated contents rather than trusting them as prepared state.
