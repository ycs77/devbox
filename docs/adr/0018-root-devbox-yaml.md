# Store Project configuration in root devbox.yaml

ADR-0030 supersedes this decision. Devbox no longer reads or writes Project configuration from `devbox.yaml`.

A Project may commit its shareable Project configuration as `devbox.yaml` directly in the Project root. The visible single YAML file starts with required integer `version: 1`; Devbox rejects unsupported schema versions, unknown keys, and invalid values with their source locations rather than inferring a version or ignoring configuration. Omitting `toolchain` leaves the complete Toolchain open to Local configuration, while a present `toolchain` mapping fixes the complete selection: listed Runtimes declare release lines, omitted Runtimes are disabled, and an empty mapping fixes a Toolchain with no Runtimes. PHP release lines must match `X.Y` such as `8.3`, while Node release lines must match `X` such as `22`; these are format checks rather than a closed support list. The file contains only the project-safe allowlist and does not represent Local configuration, generated Compose, Platform lock, credentials, or an extension directory; keeping one fixed root path makes discovery deterministic without introducing a hidden directory for the initial schema.

CLI package updates never rewrite `devbox.yaml`. A newer CLI may keep readers for multiple supported Project-configuration schema versions and adapt an older supported document to the current domain model in memory, but ordinary `init`, `config`, `sync`, and `up` preserve the file byte-for-byte. An unsupported older or newer version remains a validation failure that reports the observed version, the CLI's supported range, and the required manual Project-file action. Devbox provides no automatic or TTY-dependent Project migration and adds no generic `migrate` command; a future need for machine-authored Project configuration requires a separately designed authoring operation.
