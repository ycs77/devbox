# Keep the Platform lock provider-specific and minimal

The current machine-owned `platform-lock.yaml` uses one clean-cutover `version: 1` shape with top-level `platform`, `base`, and `runtimes` fields. `base` contains only the `ubuntu:24.04` image reference, resolved digest, and `apt` mapping with the ordered curated top-level package names; it contains no Ubuntu snapshot timestamp or package revisions. `runtimes` contains only Configured Runtime families and release lines, with no placeholders.

A Node entry contains `revision`, `archiveUrl`, `checksumsUrl`, and `releaseKeyFingerprints`; family and release-line mappings are serialized canonically, and an empty Configured Runtime set is `runtimes: {}`. `releaseKeyFingerprints` is the snapshot of the packaged release-line recipe's trusted Node signing-key policy. The lock contains no Node archive SHA-256, observed signer, keyserver URL, Ubuntu snapshot timestamp, AI Agents, Node package managers, Services, Workspace identity, Base local image ID, generic artifact list, or PHP placeholder; the Base digest remains part of the Base entry, and PHP enters the current version-1 shape only when its family-owned recipe contract is decided. Build resolves the locked Base package names from Ubuntu's live archive after the CA bootstrap, so package revision drift is intentionally outside the lock.

ADR-0047 records the corresponding Runtime verification boundary: `update` snapshots recipe-owned release-key fingerprints, while `build` verifies the signed manifest and derives the archive checksum in the inline Dockerfile.
