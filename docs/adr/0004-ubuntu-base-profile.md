# Use Ubuntu 24.04 LTS as the curated Base profile

Devbox uses one non-user-selectable Ubuntu 24.04 LTS Base profile as the shared userland ABI for the Sandbox and every Runtime recipe. Devbox is Lucas's opinionated personal development environment; his greater familiarity with and regular use of Ubuntu decide the profile. This is a product preference, not a claim that Ubuntu provides broader official multi-version Runtime packages.

Each `devbox build` uses the `ubuntu:24.04` tag as the Workspace Dockerfile base and installs the Base contents inline at the beginning of that Dockerfile. Devbox persists no Base digest, package plan, ABI generation, or recipe version, and there is no separately materialized Base image, Base tag, or Base update command.

The curated native package set is the union required by the Base tools and every Runtime recipe supported by that Devbox release. Runtime trees do not carry private copies of distribution shared libraries. This makes images without Runtimes larger, but keeps dynamic linking, library security updates, and cross-Runtime reuse in one shared Base. Adding or removing a required native package changes the packaged Base recipe and takes effect through the next `devbox build`.

The Base includes the basic native dependency build toolchain: `build-essential`, `python3`, `python-is-python3`, and `pkg-config` with their required packages. This layer is stored once in the shared Workspace image rather than once per Project. The system Python and its `python` alias are fixed Base build helpers for tools such as `node-gyp`, not a user-selected Python Runtime or an addition to the Runtime catalog.

The Base's fixed practical CLI set is `ca-certificates`, `curl`, `wget`, `git`, `openssh-client`, `zip`, `unzip`, `jq`, `less`, `vim`, `ripgrep`, `fd-find`, `procps`, `lsof`, `iproute2`, `dnsutils`, `netcat-openbsd`, `rsync`, `tree`, and `bubblewrap`; `vim` is also the default `EDITOR` and `VISUAL`. `fd-find` exposes only the distribution's `fdfind` command; the Base adds no `fd` symlink. The Base also installs internal dependencies that are not user-facing tool choices: `supervisor` for the root-owned idle supervisor, `gosu` for entrypoint user switching, `sudo` for ADR-0051's passwordless elevation, `gnupg`, `dirmngr`, and `xz-utils` for Node source verification and extraction, and `pulseaudio-utils` for Agent notifications. These tools support Agent installation, source retrieval, archive handling, repository work, search, and Sandbox diagnostics; their package revisions resolve from the live distribution archive during each Workspace build rather than from separate lock entries. `openssh-client` supplies client capability only and does not expose host SSH identity or weaken the no-host-SSH boundary.

The Base installs `tzdata` and fixes the Sandbox system timezone and `TZ` environment to `UTC`. It sets `LANG=C.UTF-8` without installing or generating a larger locale archive and leaves `LC_ALL` unset so individual processes may deliberately override locale categories. Devbox does not detect, bind-mount, or inherit the host timezone or locale; changing either opinionated default is a Base-recipe change that takes effect through the next `devbox build`.

Ubuntu 24.04's official archive supplies only its release PHP line and does not solve multi-version PHP. This decision therefore does not select a PHP installation source, accept a third-party repository, or describe one as Ubuntu support; those remain Runtime-recipe decisions with their own trust and lifecycle trade-offs. When PHP implementation begins, Devbox should evaluate Ondřej Surý's PPA and `packages.sury.org` as preferred third-party package-source candidates alongside an official-source build, without treating that interest as prior acceptance.
