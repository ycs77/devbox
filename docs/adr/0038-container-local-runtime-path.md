# Select Runtimes through the container-local PATH

> **Current status:** ADR-0048 moves Node global-tool installation into the Workspace image Build. ADR-0049 defines Project selection through Local configuration and a literal Compose `NODE_VERSION`. The entrypoint, rather than Compose, applies the selected Node `bin` directory to `PATH`.

Each Project's static Compose definition supplies the selected Node release line as `NODE_VERSION`. On container start, the entrypoint checks that the selected Node executable exists, prepends `/opt/devbox/runtimes/node/<release-line>/bin` to its environment's `PATH`, and writes the same selection to `/etc/bash.bashrc` for later Bash sessions. Processes launched by the entrypoint inherit that `PATH`; interactive Bash sessions apply the configured path on startup. A Local-configuration change takes effect when `up` applies the regenerated Compose definition, not by switching a running Sandbox.

Each family-owned Runtime recipe owns its native command layout and declares only the directories that selection adds to `PATH`. Node uses `/opt/devbox/runtimes/node/<release-line>/bin` directly, preserving the official archive's commands and the npm-global executables installed into that same prefix during Runtime Build; Devbox creates no Node command projection or relocated links. PHP's command layout, including whether and how Composer follows a PHP release line, remains deferred with the PHP recipe.

Stable command shims are rejected as the core selector because runtime-dispatch wrappers would have to preserve transparent argument, signal, exit-status, and shebang behavior and would add selection logic that native Runtime command directories avoid. Runtime existence checks and non-Selected Runtime access remain separate decisions.

Command names exposed by different Runtime families' managed PATH entries are globally unique. Devbox rejects a catalog or managed-tool definition that introduces a cross-family collision rather than silently choosing a winner through `PATH` precedence. The Compose renderer still orders Selected Runtime directories canonically to produce deterministic bytes, but that order has no command-selection meaning.

`nvm` remains outside the Devbox-managed Toolchain: Devbox does not install, configure, or support it as either the core selector or an optional interactive facility. A user may still install and activate it in writable Sandbox state, but that self-managed process-local override does not change the Selected Runtime, does not participate in selector preflight or bootstrap, is not promised to affect other shells, Compose-exec processes, or AI Agents, and may disappear with container replacement.

Devbox does not support temporarily switching a Sandbox process to a non-Selected Runtime through an absolute executable path or a process-scoped `PATH` override. The supported way to change a Project's release line is to change Local configuration and run `up` so the container environment follows the retained Compose definition. Because other Configured Runtimes remain physically present in the shared Workspace image, this is an interface rule rather than capability enforcement; user-managed direct invocation may be technically possible but receives no command-group, compatibility, selector-preflight, or lifecycle guarantee.

PATH omission is not a security control. Any Sandbox-user process, including an AI Agent or Project command, may inspect the shared image and invoke another physically present Configured Runtime by absolute path or its own environment. Devbox neither prevents nor endorses that access: it remains outside Toolchain support and does not gain compatibility, selector-preflight, command-collision, or lifecycle guarantees.

The entrypoint exposes the selected Node Runtime to processes it launches, and Bash startup exposes it to later Bash sessions. When a Project selects no Node Runtime, Devbox does not add a Node Runtime directory to either path. Other installed Runtime trees remain present in the shared image but are not selected by Devbox for that Project.

The Sandbox entrypoint checks for the selected Node executable before starting the long-lived process. If it is absent from a stale `devbox-workspace:latest` image, it reports the missing release line and exits nonzero. This preflight does not execute Node or verify the final image, and `up` does not wait for the entrypoint: inspect Compose logs if the container stops immediately.
