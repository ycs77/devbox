# Keep Project choices local and make configuration self-applying

> **Current status (2026-08-14):** ADR-0048 supersedes this ADR's Global Runtime-to-Platform-lock resolution contract and defers Local configuration. The current Global build input is `build.node`; Project-specific Runtime selection will be decided later.

ADR-0034 supersedes this decision's self-applying configuration flow. `config` and `config -g` now edit only their configuration scope; exact resolution, image building, and Sandbox lifecycle are separate explicit stages. ADR-0041 also makes Configured Agents Runtime-independent first-start Sandbox inputs rather than Workspace build inputs. The Local and Global configuration ownership, schema, persistence, and no-migration decisions remain in force.

Devbox removes committed Project configuration and `devbox.yaml`; Runtime choices are entirely local to each user and may differ for the same Project across machines. A human-editable Local `config.yaml` remains the complete Project-scoped desired state with `version: 1`, a `toolchain` mapping that selects zero or one release line per Runtime family, and `ports`; it no longer stores an AI Agent. This accepts weaker cross-machine Runtime reproducibility in exchange for one simpler, user-owned configuration source and supersedes the Project/Local merge model in ADR-0002, ADR-0003, ADR-0018, and ADR-0022.

Devbox adds a user-scope Global configuration at `~/.devbox/config.yaml` with `version: 1`. It stores desired `runtimes` mappings of release-line lists and an `agents` list, corresponding to the Configured Runtime set and Configured Agent set; exact Runtime revisions and digests remain derived Platform-lock state. Devbox no longer selects one AI Agent per Project: every configured Agent is installed through its official Runtime-independent path during first-start bootstrap and available in every Project Sandbox, while each Agent retains its separately managed Agent home.

`devbox config` edits only the current Project's Local configuration, while `devbox config -g` edits only Global configuration. After confirmation, either command atomically preserves the new desired configuration and returns without resolving artifacts, modifying the Platform lock, building an image, rendering Compose, or changing Sandbox lifecycle. Supported manual YAML edits follow the same validation contract when a later command reads that scope. The public `sync` command is removed; users advance exact resolution, image materialization, retained Compose publication, and Sandbox lifecycle explicitly through `update`, `build`, and `up`.

Every current Devbox-managed file that declares a `version` keeps `version: 1` while the product is still under development with no users. Schema changes replace the version-1 contract directly; Devbox does not add version-2 writers, migration chains, backward readers, downgrade handling, or other compatibility work until a real persisted compatibility boundary exists.
