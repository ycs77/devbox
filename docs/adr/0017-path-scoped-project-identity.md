# Treat each project root as a distinct Project

ADR-0042 supersedes this decision's registration storage and unregister commit point: the machine-owned Project registry is the sole registration authority, while Local `config.yaml` contains no duplicate Project root. Exact path-scoped Project identity, Missing-root classification, and explicit removal remain in force.

Devbox identifies a Project by the existing current working directory reported by the operating system rather than Git remote, repository lineage, or extra filesystem alias detection. `devbox init` uses exactly the directory in which it is invoked as the root and never climbs to a Git top-level directory; separate subdirectories, clones, and worktrees therefore remain eligible for independent Local configuration, ports, Services, Agent state, and Sandbox lifecycle, while non-Git directories use the same model. Moving a root creates a new Project that must be initialized independently; Devbox neither infers relocation nor migrates state, and the old registration remains until that root reappears and the user runs `devbox rm`. When that exact root cannot be found, Devbox classifies the retained registration as a Missing-root Project registration without inferring why.


`devbox rm [--yes]` is a Project-local teardown and unregister operation for the current existing Project. It displays the exact Project root and the Sandbox, container writable layer, retained Compose, Local configuration, and registration selected for removal; an interactive terminal requires one confirmation, while a non-interactive caller must pass `--yes`, which bypasses only the prompt. After confirmation it applies `down` semantics, removes retained Project files and the empty mirror, then atomically removes the Project registry entry last; any earlier failure keeps the entry registered for a forward retry. It never changes Global configuration or the Platform lock and never removes Agent homes, Workspace images, or Docker volumes.

`devbox rm` does not modify Global configuration. Removing the last Local selection of a Node release line only clears that line's removal guard; it never implicitly removes the line from Global `node`, prunes the Configured Agent set, or invokes `build`. Those user-scope desired-state changes are a separate Global-scope `config` operation.
