# Treat each project root as a distinct Project

Devbox identifies a Project by the existing current working directory reported by the operating system rather than Git remote, repository lineage, or extra filesystem alias detection. `devbox init` uses exactly the directory in which it is invoked as the root and never climbs to a Git top-level directory; separate subdirectories, clones, and worktrees therefore remain eligible for independent Local configuration, ports, Services, Agent state, and Sandbox lifecycle, while non-Git directories use the same model. Moving a root creates a new Project that must be initialized independently; Devbox neither infers relocation nor migrates state, and the old registration remains until explicit cleanup. When that exact root cannot be found, Devbox classifies the retained registration as a Missing-root Project registration without inferring why; global Project listings and cleanup previews display that status together with the original absolute path.

Missing-root Project registrations are removed only by the global `devbox cleanup --missing-projects` mode. It extends the normal Cleanup plan with every currently Missing-root registration, displaying each original absolute path and the mirrored state selected for deletion in the same single confirmation as stopped Sandbox, temporary-file, and image cleanup; any running Devbox Sandbox blocks the whole combined operation before deletion. After removing planned stopped Sandbox and Compose resources, Devbox rechecks each candidate root and its resources, retains and reports any registration whose root has reappeared or whose resources still exist, and otherwise deletes its mirrored `compose.yaml`, `config.yaml`, and resulting empty directories. It never touches an original Project path or any Docker volume, and `--dry-run` and `--yes` follow the normal Cleanup contract.

`devbox rm` is a Project-local teardown and unregister operation for the current existing Project and never invokes Sync or Cleanup. It first applies `down` semantics to stop and remove that Project's Sandbox container and rebuildable Compose network, then removes the retained `compose.yaml`, deletes `config.yaml` last to end the registration, and prunes resulting empty mirror directories. A teardown or state-removal failure before `config.yaml` is deleted keeps the Project registered for a safe retry; the operation never changes the Platform lock or removes Agent homes, Workspace images, or any Docker volume.
