# Require explicit Base updates

Global `devbox update` updates locked Runtime and Service artifacts but never changes the Base point release, upstream revision, source digest, materialized image ID, or profile. Base changes require the explicit `devbox update --base` form, which expands the same update to every locked Platform artifact and always targets the last, newest Base profile in Devbox's ordered Built-in list of supported profiles. When the active lock already uses that profile, the operation still resolves its newest exact upstream revision and digest and performs a fresh native-package transaction rather than treating an old package-install cache as current.

Base update materializes and verifies one candidate local Base image, records its content-addressed image ID, assigns the derived stable tag only after verification, and rebuilds every affected existing Workspace image before atomically activating the complete candidate Platform generation. The Base list is Devbox package data rather than Project configuration, and users cannot select or pin a different profile. `--base` itself is complete consent to the cross-profile or native-package migration: the command displays the resolved plan but does not prompt again and behaves the same in interactive and non-interactive environments. A missing active Base artifact is not repaired by Sync or ordinary update; `devbox update --base` is the explicit recovery path.
