# Keep the initial CLI explicit and human-oriented

ADR-0034 adds the public global `build` command, ADR-0001 adds Project-local `logs [--follow]` for detached Sandbox diagnostics, and ADR-0045 replaces the former helper-backed lifecycle-lock model with simple command locks for the current configuration and Project operations. The current public Project-local surface is `init`, `config`, `up`, `sh`, `exec`, `logs`, `stop`, `down`, and `rm`; `config -g`, `update`, `build`, and `cleanup` are global. Devbox exposes no public `sync`, status, list, prune, recreate, Agent-authentication, Agent-reset, or generic volume-management command. New commands require a concrete need rather than a placeholder namespace.

`init` registers the current existing directory as a Project. Every other Project-local command requires that exact directory to be registered and fails with an actionable `devbox init` instruction rather than registering implicitly; Missing-root registrations remain addressable only through `cleanup --missing-projects`. `config -g`, `update`, `build`, and `cleanup` work independently of the current directory. Commands whose target state already holds are successful no-ops where Compose itself provides that behavior, including `stop` with no running container and `down` with no remaining container or rebuildable network; `up`, `sh`, `exec`, and `logs` delegate their operational result directly to Compose under their defined arguments.

`init` is interactive-only and fails with usage status outside a TTY. Under its Global command lock and its new Project command lock it presents editable Built-in suggestions informed by supported Project manifests, collecting any absent Global Configured Runtime and Agent sets plus the new Local Toolchain and ports, then asks for one final confirmation; explicit No or cancellation before confirmation writes nothing. After Yes it advances forward-only by atomically creating absent Global configuration, preparing Local configuration, and publishing the Project registry entry last, preserving any earlier successful commit if a later write fails.

`config` and `config -g` are likewise interactive-only; `-g` is the only scope switch, and the initial CLI exposes no field-level Runtime, Agent, Toolchain, or port flags. Each command loads and validates its current human-editable YAML, presents the applicable choices and guards, displays actual changes, and asks for confirmation only when bytes would change; No or no changes is a successful no-op. Non-interactive users edit the supported YAML interface directly and let later commands validate it.

For Devbox-owned outcomes, exit status `0` means success, including a no-op or an explicit No at a confirmation; `1` means validation or operational failure; `2` means CLI usage error; and interruption by Ctrl-C returns `130`. The direct Compose pass-through commands `up`, `sh`, `exec`, and `logs` instead return Compose or the attached process's status unchanged after Devbox's own argument and retained-state validation succeeds. The initial CLI exposes human-readable output only: normal results and plans use stdout, warnings and Devbox errors use stderr, and errors state the observed condition plus the next supported action. Pass-through stdout and stderr remain unmodified, while Devbox diagnostics use stderr. Devbox provides no `--json`, `--quiet`, or stable prose-parsing contract in the initial release.

When an operation encounters partially advanced release state, its error reports only the relevant states it directly observed—such as the package state, file schema and commit point, active Platform lock, verified tag, retained desired Compose, or actual Sandbox—and the next supported forward action. It never collapses npm, files, Docker, and container lifecycle into a synthetic upgrade status or claims that already committed state was rolled back.

Internal module interfaces represent expected failure as `Promise<Result<T, DevboxError>>` rather than throwing or formatting terminal prose. `DevboxError` is a discriminated union whose `kind` identifies usage, validation, or operational failure and whose data records the observed condition, next supported action, and underlying cause when present; the CLI presenter alone renders stderr and selects the public exit status. Exceptions are reserved for programming defects and process interruption, with Ctrl-C translated at the outermost operation boundary.

Ctrl-C starts cooperative forward-only cancellation through an operation-scoped `AbortSignal`: no new work is scheduled, the active Docker child receives SIGINT and is force-killed only if it has not exited after a fixed ten-second grace period, and no later candidate activation or Compose publication begins. Already committed Local or Platform state and already verified stable tags remain valid, disposable temporary state is cleaned best-effort, every acquired command marker is released, and the outer operation exits `130` after reporting the Docker state that actually remains. Forced process termination may leave a marker for manual cleanup after the user confirms that no Devbox process is running.
