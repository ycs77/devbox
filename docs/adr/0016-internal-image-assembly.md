# Keep image assembly behind Devbox operations

Devbox exposes no public `build` command or internal-artifact targets. Operations such as `sync`, `up`, Platform update, and Base update call one internal Build module directly to prepare the required Workspace images; `sync` materializes the current Project's required state without starting a Sandbox, while `up` invokes that same synchronization before start. Platform and Base update operations pass candidate state to the Build module and activate it only after every required build and verification succeeds, keeping Runtime bundle and image composition out of the CLI interface; AI Agent installation occurs later in the Sandbox entrypoint and never calls this module.

Workspace readiness and reuse require no host-side registry or verification metadata file: Build verifies a candidate before assigning its deterministic `devbox-workspace:<fingerprint>` tag, and later operations treat only that stable tag as reusable. Docker stores the image, while each retained generated Compose definition stores the Project's synchronized image reference.

`sync`, `up`, `stop`, `down`, and `rm` never opportunistically remove a superseded Workspace tag. The image-removal pass of `devbox cleanup` alone considers Devbox-owned `devbox-workspace:<fingerprint>` tags, while holding the exclusive user-scope lifecycle lock and evaluating current references rather than a stale-image list. A tag remains protected while any retained generated Compose definition references it or any existing Sandbox container uses its image; the active Platform lock does not independently protect a Workspace image because its content-fingerprint identity can be rebuilt. Replacing a retained Compose reference protects the new desired tag, while an old actual image remains protected by its running or stopped container. Once container replacement, `down`, `rm`, or Cleanup itself removes that last container and no other Project's retained Compose references the tag, the tag becomes eligible for a later Cleanup plan without a Workspace registry, dirty state, or generation record. Cleanup removes only the Devbox tag, while Docker retains the physical image if another tag or non-Devbox reference still protects it.
