# Materialize complete project configuration in user scope

The first `devbox init` for a Project runs only in an interactive terminal and materializes one complete Local configuration in user scope; the initial release provides no non-interactive initialization mode. Project configuration values are fixed and displayed without prompting, while the user answers every option the project leaves open. For an open Toolchain choice, Devbox detects supported project manifests such as `composer.json` and `package.json`, presents the inferred Runtimes and release lines as editable suggestions, and falls back to Built-in defaults when detection is inconclusive; detection never fixes a Project option automatically. Repeating `init` reports that the Project is already initialized and changes nothing, while later configuration changes use a separate operation. Before each start, current project-fixed values are synchronized into the Local configuration, and execution reads only the resulting complete configuration; removing a project-fixed value preserves its last local value but makes it user-editable. This gives projects shareable control over selected choices without requiring every personal choice to live in the repository.

`init` does not invoke Sync, create or modify the Platform lock, prepare Workspace images, render generated Compose, create or start a Sandbox, or perform any Docker operation.

Local configuration is also a supported human-editable YAML interface with its own required integer `version: 1`, independent of the Project configuration schema version. Devbox validates it before every operation and refuses unsupported versions, unknown keys, or invalid and incomplete content rather than repairing or ignoring them silently; CLI writes are atomic and use one canonical YAML format, preserving values but not comments, key ordering, or original formatting.

Devbox exposes a non-starting `devbox sync` operation that validates the current Project and Local configuration and synchronizes current project-fixed values into the Local configuration before preparing derived state. `devbox up` invokes the same Sync module automatically, so an explicit sync is optional rather than a prerequisite; operations that do not apply a new Sandbox definition use the most recently synchronized generated Compose state.

Sync commits derived state in safe dependency order rather than emulating a cross-file transaction. A valid project-fixed synchronization is atomically written to `config.yaml` even if later artifact preparation fails, because it is the current Local configuration rather than a candidate artifact; subsequent Platform and Compose steps may then be retried without rolling that configuration back.
