# Share one Installed Runtime set across Project Sandboxes

ADR-0049 defines the active Configured Runtime set as Global `node`: a Project may select only a release line already present in that set, through Local-scope `config`, and Global-scope `config` explicitly adds or removes lines. User-scope ownership, replacement-based removal, and common Workspace inclusion remain in force.

Devbox keeps one Sandbox container per Project but uses one common immutable Workspace image assembled from the Base profile and the Configured Runtime set. A Project's Toolchain still selects zero or one release line per Runtime family, while the Configured Runtime set may contain additional release lines required by other Projects; Runtime selection controls the Project's supported command resolution rather than its container boundary. This retains Project-scoped workspace, process, network, writable-layer, and lifecycle isolation without adopting a single shared container.

Users add or remove Configured Runtime entries only through explicit Global configuration. Local `config` may select only an already configured entry. Removing an entry from Global configuration requires a replacement Selected Node Runtime from the remaining Configured Runtime set, or `null`, for every registered Project that still selects it, including a Missing-root Project registration. Global-scope `config` collects those replacements before its single confirmation, then publishes the Global configuration, the replaced Local configurations, and every affected static Compose definition together; if any affected Project has no valid replacement, the removal fails without writing. The set manages only Runtime families and release lines; family recipes own Composer, PHP extensions, Node package managers, and other curated tools.

Replacement evaluates registered Projects' Local selections rather than Sandbox actual state. A running or stopped Sandbox that still uses an older Workspace image containing the Runtime does not require a replacement or block removal from the Configured Runtime set: its immutable container image reference preserves that actual state independently until later replacement, teardown, or Project removal. This keeps Global desired-state changes separate from stale container lifecycle while still requiring a replacement for Missing-root Project registrations.

The Workspace image and explicitly modeled user-scope resources such as Agent homes may be shared across Project containers. Project workspaces, container writable layers, processes, networks, and lifecycle state are never shared. Changing Global `node` requires an explicit `build` before the common image reflects it, an accepted trade-off for preparing each configured Runtime once per user.
